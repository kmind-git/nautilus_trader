## 风控责任

现有 [RiskEngineConfig](../../crates/risk/src/engine/config.rs) 提供引擎级提交/修改限频、
按合约单笔名义额及其他配置。OrderHub 需要增加提交方额度和账户总约束，
并继续经过原生 RiskEngine，不开启 `bypass` 来规避原生检查。

| 维度  | 检查内容                              |
| --- | --------------------------------- |
| 身份  | 凭证对应提交方、可用策略、账户、路由及读写权限。          |
| 合约  | 价格/数量步进、最小数量/名义额、币种、交易状态、允许的订单组合。 |
| 订单  | 单笔数量、单笔名义额、价格带、允许发送截止时间。          |
| 策略  | 已有持仓、未完成订单预占、暂占、可卖数量、活跃订单数。       |
| 账户  | 全部策略和外部未归因敞口、账户资金/购买力约束、通道限制。     |
| 数据  | 合约元数据版本、账户/行情新鲜度、交易时段及恢复状态。       |

服务端始终独立验证字段，不依赖客户端读取元数据后自行校验。
上游价格精度检查不能代替按实际 tick 大小取模、可变 tick 规则及相对市场价的价格带检查。

## 首期美股计算范围

建议首个功能闭环采用 USD 整股、买入及卖出现有持仓、常规交易时段；这是实施建议，
尚未确认融资、卖空、碎股、ETF 范围和盘前盘后支持。
不把其他资产上的 `reduce_only` 直接解释为美股券商提供相同原生保证。

全部金额和数量使用 Nautilus 精确类型或 Decimal；跨币种不得直接相加。
若后续允许多币种，必须定义汇率来源、时效、折扣和额度币种后再开放。

对于首期多头股票账户，至少独立维护买入预算、可卖数量及敞口限额：

```text
可用买入预算 = 已分配预算 - 已用成本预算 - 未成交买单预占 - 暂占 - 费用缓冲
可卖数量 = 已确认归属持仓 - 未成交卖单预占 - 卖单暂占
策略毛敞口估计 = 持仓保守估值 + 可能增加风险的未成交订单占用
账户约束 = 所有策略占用 + 外部/未知占用 + 账户级缓冲
```

现金预算与市值敞口使用不同账本口径；不使用“已用成本预算”冒充盯市敞口。
限价买单按可执行的最高限价和费用缓冲预占；市价单使用新鲜参考价格与保守缓冲估算。
市价单的估算不是最坏成交价保证。若要求硬性价格上限，需选用通道支持的限价保护或拒绝市价单。
市场跳价可能使持仓超限；硬约束保证的是准入规则，不承诺市场变化后持仓永不越界。

数据缺失、过期、未对账或无明确资产计算规则时拒绝新增风险。阈值为部署必填配置，
不能把无限超时或未知账户余额当作正常值。

## 原子检查与预占

核心线程串行执行“检查 + 暂占”，持久化事务成功后转为正式预占。
暂占参与后续检查，因此异步磁盘提交期间不会重复使用同一额度。
多层限额一并检查；任意策略、合约或账户约束失败都不产生部分预占。

例如剩余预算 100，两笔并发买单分别需要 60，最多允许一笔进入受理事务。
批量落盘可减少同步提交次数，但批次内仍按准入顺序分配额度。

| 状态变化                  | 额度动作                         |
| --------------------- | ---------------------------- |
| 事务提交前明确失败且未发送         | 回滚暂占。                        |
| 事务提交结果未知              | 保留占用并停新单，恢复后确定结果。            |
| 订单持久受理                | 暂占转为正式预占。                    |
| 原生风控/通道明确拒绝、确认本地未发即过期 | 持久记录结果后释放对应预占。               |
| 部分成交                  | 将成交部分转为持仓/资金占用，保留剩余订单及费用缓冲。  |
| 待撤、超时、断线、发单不确定        | 不提前释放额度。                     |
| 确认撤销或到期终态             | 结合累计成交释放剩余预占。                |
| 迟到成交、成交撤销或修正          | 按事件身份幂等修正账本；证据不完整时停相关账户新增风险。 |

事件去重需要稳定成交身份及适配器约定，不仅依靠到达时间或累计数量。
订单结果、额度变化和对外事件在同一业务事务中提交，重复回报不会重复释放或重复增加持仓。
费用迟到时保留缓冲，到账后结转；规则版本和计算依据应可追溯。

## 归属与账户边界

`strategy_id` 是归属标签，`TraderId` 不是风险隔离边界。
账户级额度汇总所有策略及外部未知订单；客户端无权通过改策略 ID 获得额外账户资金。
建议首期每个账户合约组合只分配给一个策略，避免仅有券商净持仓时无法恢复多个策略账本。

后续共享 NETTING 必须持久保存策略成交归属；不能把 A 的 +10、B 的 -8 持仓仅以账户 +2 替代。
禁止用反向挂单即时抵销买入预算，因为一边可能先成交而另一边未成交。
`reduce_only` 需要同时定义策略级和账户级效果；减少某策略持仓可能增加账户净风险。

## 速率与排队

系统接入能力、策略速率配额、原生风控速率和执行通道额度分别配置并同时生效。
1000 提交/s + 1000 撤单/s 的接入目标不覆盖上游限流。

- 每个通道设置共享总消息预算，扣除提交、撤单及需要计入配额的查询/管理请求。
- 为撤单和必要对账预留带宽；新单不能占满全部通道额度。撤单仍服从通道总上限。
- 队列同时限制条数、字节数及最大等待时间；超过容量在受理前拒绝，不无限堆积。
- 持久受理后过期的未发送新单产生明确本地终态；撤单不因普通新单发送截止而被静默丢弃。
- 按提交方公平调度，防止一个策略耗尽全局内存；不要通过增加连接绕过券商账户级限制。
- 原生提交限频默认值需要在容量验证中显式配置，不能将其拒单吞吐当作成功受理吞吐。

详细测量口径见 [美股接入与容量](venues-and-capacity.md)。

## 验收场景

| 编号  | 场景                   | 必须成立                    |
| --- | -------------------- | ----------------------- |
| R01 | 两笔请求竞争同一剩余额度。        | 含暂占的总占用不超过准入额度。         |
| R02 | 多策略同时使用同一账户。         | 策略限额和账户总限额同时生效。         |
| R03 | 冒用策略 ID、跨策略撤单/查询/订阅。 | 服务端拒绝越权，不泄露未授权订单详情。     |
| R04 | 重复成交、迟到费用、成交修正。      | 不重复结转；超限或证据缺失时阻断新增风险。   |
| R05 | 待撤订单在撤单确认前收到成交。      | 预占未提前释放，持仓和剩余额度正确。      |
| R06 | 行情/账户过期、交易暂停、元数据变更。  | 新单被拒；允许的撤单仍走独立控制路径。     |
| R07 | 新单洪峰与撤单同时到达。         | 撤单预留带宽有效，队列有界，符合通道共享限额。 |
| R08 | 微小数值、非合法 tick、极大数量。  | 使用精确运算，拒绝无效步进及溢出。       |
